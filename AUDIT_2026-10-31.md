# Routix — technical audit (2026-10-31)

## Scope and method

Targeted review of Android application components: RoutixActivity, MapStyles,
ModernMapController, VelaMapStyle, RouteStore, RouteArchive/RouteExporter,
PersistentRouteBackup, SessionJournal, TrackingService, FranceOfflineManager,
RoadContextProvider and InAppUpdater, plus AndroidManifest and the debug CI workflow.
This is a source review plus automated CI tests, **not** a certification of all
runtime paths on every Android device. Critical on-device tests remain below.

## Implemented changes

| Area | Finding / change | Risk |
| --- | --- | --- |
| Basemap | Optional Vela Maps look uses **live** OpenFreeMap Liberty, with Vela's modern light/dark palette, road hierarchy, polygons, 3D buildings and house-number layer. Existing Routix basemap remains available and offline Mapsforge maps remain separate. | Feature |
| Basemap | Palette-aware style key reloads Liberty when day/night changes, even though the remote style URL stays constant. | Medium |
| App theme | Window navigation-bar color is initialized after theme tokens, not from an uninitialized integer. | Low |
| Updater | Debug build number comparison corrected to the 300000 + GitHub run-number scheme from Gradle; displayed version updated. | High |
| Updater | Reject plain HTTP redirects, bound artifact download (330 MiB) and extracted APK size (300 MiB). | Medium |
| Saved routes | Do not set the route-deletion tombstone or erase its metadata/backups before a successful file deletion. | High |
| Route copy | Remove partially created duplicates on errors. | Medium |
| GPX import | Bound copied GPX input at 128 MiB to reduce memory/storage abuse risk. | Medium |
| CSV export | Escape formula-like marker labels so spreadsheets don't execute them as formulas. | Medium |
| Attribution | Credits reference Vela's GPL-3.0 palette and OpenFreeMap/OSM providers. | Compliance |

## Automated validation

- GitHub Actions builds Android debug APK using JDK 17 / Gradle 8.13.
- Workflow executes \`:app:testDebugUnitTest\` and \`:app:assembleDebug\`.
- New Robolectric/JUnit tests:
  - \`VelaMapStyleTest\`: opt-in style, default legacy basemap, dark-mode reload key, restore legacy.
  - \`RouteDeletionSafetyTest\`: failed deletion preserves favorites, labels and nondeleted status.
  - \`RouteExportSafetyTest\`: spreadsheet formula injection protection.

The GitHub "Dependency Review" check may fail on this repository **because
GitHub Dependency Graph is disabled**, independently of source compilation.
It requires repository security settings to be enabled by its owner.

## Manual device regression checklist (still required)

1. Android 13–17: toggle Routix/Vela then light/dark/automatic night; confirm all map layers load with network and return to existing style without blanking or crashing.
2. Verify Vela cartography (road hierarchy, POIs, 3D buildings and housenumbers) at several zoom levels with OpenFreeMap network access; remote OpenFreeMap availability remains a dependency.
3. In an existing recording: swap basemap and confirm track, position puck, marker labels, route arrows and navigation progress survive style reload.
4. Import and export GPX/KML/CSV, duplicate/rename/delete a route, interrupt a recording with process death and restore it.
5. Confirm offline France/Alsace Mapsforge packs still work and that Vela online mode does not pretend to work offline.
6. Verify actual debug APK update installation over the previous build and OS "install unknown apps" consent.
7. Check font/sprite network errors, map label visibility and graphics-driver stability on real hardware.

## Residual risks / follow-up

- New map style is online-only; downloaded Mapsforge maps remain drawn with their own renderer.
- Vela has its own rich POI search/categories, traffic and navigation code; those were **not transplanted**, only the visual basemap and selected styling.
- Robolectric unit tests cannot validate MapLibre's actual GPU rendering or proprietary Android/OriginOS graphics drivers.
- Github Actions dependency-review is an account configuration issue until Dependency Graph is enabled.
- Android \`allowBackup=true\` currently backs up app data according to the user's OS settings; for privacy-sensitive route histories this should be reviewed in a separate backup-policy change, not silently removed.
- The updater depends on GitHub Actions artifacts that expire according to repository retention, and device installation depends on Android package signature/permissions.
